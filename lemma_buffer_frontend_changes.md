# Буфер лемм — изменения для фронта

## 1. GET /lemma/buffer

**Убрано:** `times_selected`

**Добавлено** (в каждый элемент `items[]`):
- `weights: { [column: string]: number } | null` — веса ЦКМ по 10 измерениям. `null`, пока не сгенерированы/не введены.
- `category: string | null` — категория. `null`, пока не задана.

**Сортировка изменилась:** раньше — по количеству выделений (частые сверху), теперь — по времени первого выделения, по возрастанию (первая выделенная лемма — первая в списке).

Когда `weights`/`category` заполнены, элемент буфера уже в том же формате, что принимает `/lemma/append` (`lemma`, `weights`, `category`) — остальные поля (`raw_text`, `first_seen_at` и т.д.) append просто проигнорирует, если их туда передать.

## 2. POST /lemma/buffer

Появилось новое значение `action`: **`set_weights`** — сохранить веса/категорию для леммы, которая уже есть в буфере.

Запрос:
```json
{
  "action": "set_weights",
  "weights_items": [
    { "lemma": "инфляция", "weights": { "Власть": 0.2, "...": 0.0 }, "category": "Экономика" }
  ]
}
```

Ответ:
```json
{ "action": "set_weights", "updated": 1, "not_found": [] }
```
`not_found` — леммы, которых не оказалось в буфере (например, опечатка или лемма уже была удалена/добавлена в словарь) — такие пропускаются, не падают ошибкой.

Остальные action (`add`, `remove`, `clear`) — без изменений в формате запроса. У `add` только поведение изменилось: повторное выделение той же леммы больше не двигает её в списке (раньше поднимало счётчик).

## 3. POST /lemma/append

Новый query-параметр: **`overwrite_existing`** (`true` по умолчанию — старое поведение, ничего не сломается, если его не передавать).

- `overwrite_existing=true` (по умолчанию) — если лемма уже есть в словаре, её строка перезаписывается новыми весами.
- `overwrite_existing=false` — существующие леммы не трогаются вообще. Такие леммы попадают в новое поле ответа `already_in_dictionary`.

Новое поле ответа:
```json
{
  "lang": "ru",
  "added": 3,
  "updated": 0,
  "skipped_duplicates": [],
  "already_in_dictionary": ["привет"]
}
```
`already_in_dictionary` — леммы, которые уже были в словаре и не были добавлены заново (только при `overwrite_existing=false`).

Также **append теперь сам чистит буфер**: после ответа все леммы, отправленные в этом запросе, удаляются из буфера текущего пользователя — независимо от того, добавлены они, перезаписаны или пропущены как дубли. Отдельно вызывать `POST /lemma/buffer action=remove` после append не нужно.

## Пайплайн работы с буфером (коротко)

1. **Выделение на фронте.** Пользователь выделяет слово/словосочетание где угодно (пост, тренд и т.д.) → фронт вызывает `POST /lemma/buffer` с `action=add`. Повторное выделение той же леммы просто игнорируется (дубля не будет, порядок не меняется).

2. **Просмотр буфера.** Пользователь открывает буфер → `GET /lemma/buffer?lang=...`. Список отсортирован по порядку выделения. У каждой леммы видно, есть ли она уже в словаре (`in_dictionary`) или в чёрном списке (`in_blacklist`), и заполнены ли уже `weights`/`category`.

3. **Простановка весов — по каждой лемме отдельно.** Для леммы либо:
   - жмём "Сгенерировать веса" → `GET /lemma/trend-candidates/{lemma}/weights?lang=...` (несмотря на название пути, работает для любой леммы, не только трендовой) → получаем `{lemma, weights, category}`;
   - либо пользователь вводит веса вручную сам.

   В обоих случаях результат сохраняем в буфер: `POST /lemma/buffer` с `action=set_weights`. Веса при повторном выделении той же леммы не пересчитываются автоматически — только через явный `set_weights`.

4. **Сохранение в словарь.** Когда у нужных лемм в буфере проставлены веса, фронт собирает `items` из `GET /lemma/buffer` (у которых `weights`/`category` не `null`) и шлёт их в `POST /lemma/append?lang=...`. Дубликаты относительно словаря можно либо перезаписать (`overwrite_existing=true`, по умолчанию), либо пропустить, оставив как было (`overwrite_existing=false`, тогда они вернутся в `already_in_dictionary`).

5. **Автоочистка.** После успешного append все отправленные леммы сами исчезают из буфера — можно сразу заново открывать буфер, они там уже не появятся.
